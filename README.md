# Сервис форм отклика

Менеджер сам собирает форму отклика в админке, публикует её по ссылке и смотрит ответы. Студент открывает ссылку и заполняет форму. Дополнительно сервис показывает, на каком вопросе студенты бросают заполнение.

## Запуск

Нужен Node.js 20 или новее.

```bash
npm install
npm start
```

- Админка: http://localhost:3000/admin (без авторизации)
- Публичная форма: ссылка вида `http://localhost:3000/f/<slug>`, её показывает админка после публикации
- Порт меняется переменной окружения: `PORT=4000 npm start`

Внешних зависимостей нет: `npm install` ничего не скачивает. Данные хранятся в `data/db.json` (создаётся при первом запуске).

## Что умеет

**Админка**
- Создание, редактирование и удаление форм
- 8 типов вопросов: короткий и длинный текст, email, число, дата, выпадающий список, один вариант, несколько вариантов
- Обязательные вопросы, порядок вопросов (выше/ниже), описание формы
- Публикация и снятие с публикации: закрытая форма по ссылке недоступна
- Ответы по каждой форме и выгрузка в CSV
- Аналитика: сколько человек открыли форму, начали и отправили, и на каком вопросе остановились остальные

**Форма для студента**
- Индикатор заполнения
- Валидация на сервере с подсветкой вопросов (email, число, дата, варианты, обязательные)
- Черновик в браузере: ответы не теряются при перезагрузке или случайном закрытии вкладки

## Как решается проблема брошенных форм

Страница формы отправляет анонимные события: открыл форму, перешёл к такому-то вопросу. Последний вопрос, до которого дошёл студент без отправки, считается местом отказа. В админке это таблица «Где бросают заполнение». Так менеджер видит, какой вопрос стоит убрать или упростить. Черновик в браузере снижает потери из-за случайных закрытий.

## Структура

```
server.js          HTTP-сервер, API, валидация, хранилище (JSON-файл), аналитика
public/admin.*     админка (одна страница, hash-роутинг)
public/form.*      публичная форма
public/common.js   общие хелперы фронтенда
public/style.css   стили
```

## Принятые решения

- **Без зависимостей и фреймворков.** Запуск строго двумя командами не зависит от сборки нативных модулей (SQLite потребовал бы компиляции или Node 22+). Для MVP достаточно JSON-файла.
- **Запись атомарная:** во временный файл, затем переименование, поэтому база не повреждается при остановке в момент записи.
- **Безопасность:** интерфейс строится через DOM API, а не через HTML-строки, поэтому ответы студентов не исполняются как код. Ограничен размер запросов. Значения в CSV защищены от формул Excel.
- **Снимок вопросов в каждом ответе.** Если менеджер потом изменит форму, старые ответы остаются читаемыми.

## Ограничения MVP

- Нет авторизации в админке (так требует задание). В продакшене её нужно добавить.
- Нет защиты от спама и повторных отправок (капча, лимиты).
- JSON-файл подходит для сотен и тысяч ответов, для больших объёмов нужна СУБД.
- Нет условной логики, загрузки файлов, шаблонов форм и уведомлений менеджеру.
- Аналитика считает посетителя по браузеру (идентификатор в localStorage), а не по человеку.

## API

| Метод | Путь | Назначение |
|---|---|---|
| GET/POST | `/api/forms` | список, создание |
| GET/PUT/DELETE | `/api/forms/:id` | чтение, изменение, удаление |
| GET | `/api/forms/:id/responses` | ответы |
| GET | `/api/forms/:id/stats` | воронка и отказы |
| GET | `/api/forms/:id/export.csv` | выгрузка CSV |
| GET | `/api/public/:slug` | форма для студента |
| POST | `/api/public/:slug/event` | событие аналитики |
| POST | `/api/public/:slug/submit` | отправка ответов |
